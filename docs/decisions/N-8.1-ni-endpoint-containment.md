**Review points not adopted, with reasons** (engineering disagreement, stated openly):

- **Stall definition.** The review proposed `stall = responsibility && noc_rx_valid && !rx_ready`. **Not adopted.**
  - On a rejected flit the NI drives `noc_rx_ready = 1` whatever `rx_ready` is.
  - That definition would therefore count a stall in a cycle where the flit is actually **accepted**. That is a false count, and it opens a hole the review itself was trying to close.
  - Adopted instead: `stall = responsible && noc_rx_valid && !noc_rx_ready`, plus an SVA stating that `noc_rx_ready` is low only while the tile's `rx_ready` is being forwarded (§5).
- **Bound assumption "no FIFO empty gaps alter the service sequence".** **Not adopted.**
  - It is false for any real run.
  - It is also not needed: the per-flit arbitration argument in §9.5 holds for any gap pattern, because gaps can only remove contention.
  - The actual assumptions are listed in §9.5.
- **Mutation numbering.** The review used "M-n6" twice: once for "slot not freed on containment" (its point 11) and once for "DISCARD does not force ready" (its point 20). Resolved as follows:
  - M-n5 covers the slot leak on *both* framing discard and containment;
  - M-n6 = DISCARD ready stuck at 0;
  - M-n7 = expiry off by one.

**Implements:** M-F1 rev 3 §10, FD-1 B′.
- The property was frozen and signed.
- The mechanism is this document.

**Source of truth:** the RTL at `acd1f73`, on branch `noc/credit-integration` (HEAD `d6035ed`; later commits are docs only). Files read for this document:
- `noc_network_interface.sv`: RX combinational L795–925, RX next-state L930–1000, TXN free L625–665, head checks L695–740, TX L255–345.

Every RTL behaviour quoted below was read from those lines.

**Hard constraints:**
- **No router change.** The allocator, credits, the eject path and every `noc_router.sv` line stay as they are. The only exception is a package define in §11.4, which leaves the default unchanged.
- **The watchdog is not the proof of forward progress.** The proof is the finite workload in §9: competing traffic completes, the network drains, and the report persists. The watchdog is only the mechanism that makes this possible.

## 0. Answers at a glance

| # | Question | Answer (section) |
|---|---|---|
| 1 | When does HEAD ownership begin? | **Responsibility** starts at *presentation*: cycle t0, the first cycle a deliverable HEAD/HEAD_TAIL is valid at the NI in RX_IDLE. The watchdog is armed from t0. **Ownership** (M-F1 rule 2) starts at the cycle the HEAD is accepted. It ends when the terminator is accepted. (§2) |
| 2 | What terminates a packet? | Only the flit **type**. At position 0 the terminator is HEAD_TAIL; at position ≥1 it is TAIL. (§3) |
| 3 | Framing errors | The rule depends on the state, because DISCARD means "the router holds an open wormhole into this NI". A **rejected HEAD** in IDLE, or a **rejected mid-packet non-terminator**, sends the NI to DISCARD. A **rejected terminator**, or an **orphan BODY/TAIL in IDLE** (F8), leaves it in IDLE. ## 1. Current RTL behaviour (the baseline being changed)

| Where | Today | Problem |
|---|---|---|
| RX_IDLE, deliverable HEAD (L827) | `noc_rx_ready = rx_ready` | The tile can stall the **HEAD itself**. M-F1 rule 6 counts only "packet owned", which begins at acceptance, so this stall is never counted. (Gap A) |
| RX_IDLE, HEAD with bad length (L840, L940) | `rx_length_error` is pulsed, but the HEAD is still **delivered** (`noc_rx_ready = rx_ready`, `rx_head_valid = 1`). The next state ignores `rx_head_len_ok`. | The NI then counts payload by msg_type, not by length. The router and the NI can disagree about where the packet ends. |
| RX_PAYLOAD exit (L962–969) | Leaves on `(BODY‖TAIL) && cnt+1 ≥ n` | Exits on the **counter**, not on TAIL. A premature TAIL or an extra BODY misaligns packet boundaries. (Known framing bug, M-F1 §10) |
| RX_PAYLOAD, HEAD arrives | Consumed as a protocol error; NI stays in PAYLOAD | The next packet's BODY flits are counted as this packet's payload. |
| RX_IDLE, rejected HEAD (L815) | Consumed; NI stays IDLE; each following BODY is consumed as its own protocol error until the TAIL | Behaves like a discard only by accident, and raises N errors for one event. |
| RX_MAC (L897) | `noc_rx_ready = 1`; exits on the MAC **counter** | Same counter-exit bug in MAC mode. |
| TX_PAYLOAD (L337) | `noc_tx_valid = tx_payload_valid` | A tile can stop supplying after the HEAD, which holds the wormhole indefinitely. (Gap B, §8) |
| TX, reserved msg_type 8–15 | `message_to_vc` → VC0, `message_length` → 1 (a HEAD_TAIL); `tx_error` checks the destination only | A reserved type is sent. The receiver's shape check passes (payload 0, HEAD_TAIL) and the tile receives it. (Gap C) |
| TXN slot free (L625–665) | Freed on a delivered response's TAIL, final MAC flit or HEAD_TAIL | Not freed if the response is discarded. N_OUTSTANDING=2 would leak. (Gap D) |

## 2. RX ownership — exact cycles (Q1)

**Definitions.** k is the position within the packet: the HEAD is k=0, and k counts accepted flits.

- **accept_t** = `noc_rx_valid && noc_rx_ready`
- **deliverable HEAD** means all of the following:
  - the flit type is HEAD or HEAD_TAIL, in RX_IDLE;
  - it is addressed to us;
  - its shape is OK;
  - its length is OK;
  - msg_type ≤ 7;
  - its VC equals `message_to_vc(msg_type)`;
  - if it is a memory response, it matches an outstanding transaction.
  Anything else is **rejected** (§4).

**Timeline:**

| Cycle | Event | NI obligation |
|---|---|---|
| t0 | First cycle with RX_IDLE ∧ `noc_rx_valid` ∧ deliverable HEAD | **Responsibility begins.** The watchdog is armed. `rx_head_valid=1` to the tile, and `noc_rx_ready = rx_ready`. If `rx_ready=0`, t0 is stall cycle #1. |
| t_acc ≥ t0 | accept_t on the HEAD | **Ownership begins** (rule 2). A HEAD goes to RX_PAYLOAD, or to RX_MAC if payload_n=0 and MAC is on. A HEAD_TAIL is a terminator: back to IDLE and the watchdog clears. |
| t_acc+1 … | Each cycle with `noc_rx_valid=1` and a BODY/TAIL in the payload region | `noc_rx_ready = rx_ready`. If `rx_ready=0` the cycle is a stall and counts; this includes `rx_ready=0` in the cycle right after the HEAD. If `noc_rx_valid=0`, the cycle is not a stall and the counter holds. |
| MAC region | BODY/TAIL MAC flits | `noc_rx_ready = 1` always. The NI consumes them itself, so a MAC flit is never a tile stall. |
| t_term | accept_t on the terminator | Ownership and responsibility end. Next state is IDLE and the counter goes to 0. |

**Release (router side, unchanged).** Each router releases its per-port lock when that router's allocator grants the TAIL (`allocator.sv` L470–476). R5.L is released when the TAIL is granted into the eject stage. That grant needs a LOCAL VC credit, and credits return only when the NI pops the eject FIFO. So the NI's acceptance is what drives every release upstream.

**Why responsibility starts before acceptance (Gap A).**
- Before acceptance, the router has already granted the HEAD to R5.L and locked it.
- A tile that never takes the HEAD therefore holds R5.L and everything upstream, exactly like a mid-packet stall.
- A HEAD_TAIL takes no lock, but a stalled HEAD_TAIL blocks the eject FIFO head. The next packet to this tile then locks R5.L behind it.
- Both cases are covered by counting from t0. This is proposed amendment AM-1 (§12).

**Assumption, checked by SVA:** once `noc_rx_valid` rises it stays high, with the flit stable, until accepted. The router side is SVA `a_local_out_flit_hold`, and `out_valid_local = !eject_empty` is registered. So `noc_rx_valid` can never drop mid-stall. The NI will carry a matching assumption assertion. If the assertion ever fired, the defined behaviour is: the counter holds and the packet stays owned (§5).

## 3. Terminator semantics — one rule for both MAC modes (Q2, Q6)

```
terminator(k, type) = (k == 0 && type == HEAD_TAIL) || (k >= 1 && type == TAIL)
```

**This mirrors the allocator exactly:**
- On a free output, HEAD_TAIL takes no lock (L484).
- On a locked output, only a TAIL from the owner releases it (L470).
- A mid-packet HEAD or HEAD_TAIL from the owner does **not** release. It fires assertion A4 (L698–725) and the lock stays held.

So the NI treats a mid-packet HEAD_TAIL as a non-terminator too. Otherwise the NI would think the packet had ended while the router still holds it.

| Mode | Length L | Expected type at position k |
|---|---|---|
| MAC off | 1 + n | k=0 HEAD (or HEAD_TAIL if n=0) · 1..L−2 BODY · L−1 TAIL. The last payload flit is TAIL. |
| MAC on | 1 + n + 4 | k=0 HEAD · 1..n BODY (payload; the last payload flit is **BODY**) · n+1..L−2 BODY (MAC) · L−1 TAIL (last MAC flit) |

- **Counters.** `rx_payload_cnt` and `rx_mac_cnt` remain, but only for:
  - selecting the region (payload is delivered to the tile; MAC is consumed by the NI);
  - `rx_payload_last` / `rx_mac_valid` to the tile;
  - **detecting** framing errors.
- **Counters never end ownership.** A TAIL at the wrong position is still a terminator, because the router has released. A BODY at the position where TAIL was expected is still a non-terminator, because the router still holds.

## 4. Framing-error policy (Q3)

**Principle.** The NI's view of packet boundaries must follow the router's. So:
- a rejected flit is always **consumed** (`noc_rx_ready = 1`);
- whether the NI then goes to IDLE or DISCARD depends only on `terminator(k, type)`;
- if a packet had already been partly offered to the tile, `rx_abort` pulses and the tile must drop what it received.

**Reporting.** Every row below:
- sets `ni_framing_sticky` and increments `ni_framing_cnt` (§7);
- keeps the existing `rx_protocol_error` / `rx_length_error` pulse where one applies.

| # | Case | Where detected | noc_rx_ready | Deliver? | Next state | Tile sees |
|---|---|---|---|---|---|---|
| F1 | **Premature TAIL**: TAIL at k < L−1. With MAC on, any TAIL in the payload region is premature. | PAYLOAD / MAC | 1 | no | **IDLE** (it is a terminator; the router released) | `rx_abort`, `rx_protocol_error` |
| F2 | **BODY where TAIL expected** (k = L−1, type BODY; the packet is longer than declared) | PAYLOAD / MAC | 1 | no | **DISCARD** (to the real TAIL) | `rx_abort`, `rx_protocol_error` |
| F3 | **HEAD_TAIL for a multi-flit msg_type** (shape fails) | IDLE | 1 | no | **IDLE** (HEAD_TAIL at k=0 is a terminator; the router took no lock) | `rx_protocol_error` |
| F3′ | **HEAD for a zero-payload msg_type with MAC off** (shape fails) | IDLE | 1 | no | **DISCARD** (the router locked; TAIL expected later) | `rx_protocol_error` |
| F4 | **Length field ≠ message_length(msg_type)**, too short or too long. Today this HEAD is delivered; that changes. (AM-6) | IDLE | 1 | no | HEAD → DISCARD · HEAD_TAIL → IDLE | `rx_length_error` |
| F5 | **VC mismatch, including illegal VC 3**: HEAD vc ≠ `message_to_vc(msg)`, or BODY/TAIL vc ≠ the packet's VC | IDLE / PAYLOAD / MAC | 1 | no | By `terminator(k, type)` | `rx_protocol_error` (+ `rx_abort` mid-packet) |
| F6 | **Truncated packet**: the sender stops and no TAIL ever arrives | PAYLOAD / DISCARD | n/a (`noc_rx_valid=0`) | — | **Stays** in PAYLOAD or DISCARD | nothing |
| F7 | **Mid-packet HEAD or HEAD_TAIL** (router A4 class) | PAYLOAD / MAC | 1 | no | **DISCARD** (not a terminator, mirroring the allocator) | `rx_abort`, `rx_protocol_error` |
| F8 | **Orphan BODY/TAIL in IDLE** | IDLE | 1 | no | **IDLE** | `rx_protocol_error` |
| F9 | **Reserved msg_type 8–15** (AM-5) | IDLE | 1 | no | HEAD → DISCARD · HEAD_TAIL → IDLE | `rx_protocol_error` |
| F10 | Not for us / unmatched memory response (existing checks) | IDLE | 1 | no | HEAD → DISCARD · HEAD_TAIL → IDLE (a change from today's "stay IDLE, one error per flit") | `rx_protocol_error` |

**F6 is a protocol boundary, not a containment case (M-F1 §10).**
- Only a terminator releases. The watchdog does not advance, because `noc_rx_valid=0` means the tile is not the one stalling.
- Nothing times out. The test documents the resulting permanent stall.
- Detecting this on the sender side belongs to S-8/N-10.
- Under this design, a trusted NI TX **cannot** truncate a packet (§8), so F6 needs a buggy or hostile NI, not a tile.

**F8 stays in IDLE, not DISCARD.**
- With the per-port lock, LOCAL output never interleaves packets, so a well-formed router cannot deliver an orphan.
- If one does appear, staying in IDLE means the next real HEAD is still recognised.
- DISCARD is entered only when the router is known to hold an open wormhole into this NI, that is, after a HEAD.

**VC 3 end to end** (closes M-F1 §11):
- **NI TX:** it cannot emit VC 3. `message_to_vc` maps every msg_type onto {0, 1, 2}, with reserved types defaulting to 0. New SVA `a_tx_vc_legal`: `noc_tx_valid |-> noc_tx_flit.vc_id != 2'd3`.
- **Router:** LOCAL-in accepts and drops VC 3 (`in_ready_local = 1`; the datapath writes only VC 0–2). **Unchanged.**
- **NI RX:** F5. This is only reachable in a unit test, because the router never forwards VC 3.

## 5. Watchdog — exact definition (Q4)

**Parameters**
- `WD_ENABLE` (bit, default 1).
- `WD_LIMIT` = W (int ≥ 1).
- Counter width `WD_W = $clog2(W+1)`.
- An elaboration check requires `$fatal` unless W ≥ 1.

**Counter range (rev 1).**
- `wd_cnt_q` holds the number of tile-stall cycles *already accumulated* in the current packet. Its range is **0 … W−1**.
- It never holds W: the cycle that would make it W is the expiry cycle, and that cycle resets it to 0 (below).
- `$clog2(W+1)` bits is deliberately one value wider than needed. It works for every W ≥ 1 with no special case (W = 1 gives 1 bit), and the extra value W is unused.
- SVA `a_wd_range`: `wd_cnt_q < WD_LIMIT` in every cycle.

**Signals.** Responsibility is a state predicate. Stall is defined on the *actual* backpressure the NI puts on the router.

```
responsible_t = (rx_state_q == RX_IDLE    && deliverable_head_t)   // HEAD/HEAD_TAIL presented (AM-1)
              ||(rx_state_q == RX_PAYLOAD)                         // owned packet, payload region
stall_t       = responsible_t && noc_rx_valid && !noc_rx_ready
expire_t      = WD_ENABLE && stall_t && (wd_cnt_q == WD_LIMIT-1)
term_acc_t    = accept_t && terminator(k, flit_type)
```

**Why stall is defined on `noc_rx_ready`, not `rx_ready`.** `noc_rx_ready` is the real backpressure seen by the router.
- The NI drives it to 1 in every case except one: forwarding the tile's `rx_ready` for a legal deliverable flit.
- So `noc_rx_valid && !noc_rx_ready` is, by construction, exactly a tile-induced stall.
- A rejected flit (ready forced to 1) can therefore never be counted, whatever `rx_ready` is.
- RX_MAC and RX_DISCARD can never stall, because they are ready = 1 by construction.

Enforced by SVA `a_ready_low_only_for_tile`:

```
noc_rx_valid && !noc_rx_ready |-> responsible_t && !rx_ready
```

This SVA is also the mutation oracle for M-n6 (§11.5).

**Invariant I-N81-WD.** For every packet, the number of cycles with `stall_t = 1` between t0 and either (a) acceptance of its terminator or (b) containment is **≤ W**. Equality holds only for a contained packet, whose W-th stall cycle is the expiry cycle.
- Checked by an independent TB counter per packet.
- Attacked by mutants M-n2, M-n3 and M-n7.

**Recurrence** (one `always_ff`; active-high `rst`, like the rest of the NI)

```
if (rst)                                  wd_cnt_q <= 0;
else if (expire_t)                        wd_cnt_q <= 0;           // entering DISCARD
else if (term_acc_t || enter_discard_t)   wd_cnt_q <= 0;           // packet boundary
else if (stall_t)                         wd_cnt_q <= wd_cnt_q + 1;
else                                      wd_cnt_q <= wd_cnt_q;    // accept of a non-terminator, or valid=0: HOLD
```

**Answers**

| Question | Answer |
|---|---|
| Is the counter reset by accepting a flit? | **No.** It is per packet and cumulative. It resets only at the packet boundary (terminator accepted) or on DISCARD entry. **Why:** a per-stall-episode counter can be defeated by a slow drip. A tile that accepts one flit every W−1 cycles never trips it, and holds the wormhole for up to L·(W−1) cycles: 17·(W−1) with MAC off, 21·(W−1) with MAC on. A per-packet counter caps the tile's total stall at W. |
| Increment | +1 on every stall_t cycle. |
| `noc_rx_valid = 0` | **Hold.** It neither advances nor resets (M-F1 rule 6). By §2 it cannot happen mid-stall with this router; it happens only between flits when upstream has none. |
| Is the expiry cycle counted? | **Yes.** Expiry is the W-th stall cycle of the packet; `noc_rx_ready` is still 0 in it. `rx_state` becomes RX_DISCARD at that clock edge. |
| Maximum stall | **Exactly W tile-stall cycles per packet.** Forced acceptance starts in the next cycle. With contiguous stalls from t0: stall cycles t0 … t0+W−1, expiry at t0+W−1, first forced accept at t0+W. |
| Timing | `expire_t` → `rx_state_d` is registered. `noc_rx_ready` depends only on `rx_state_q` (registered) and the existing flit decode. **The counter is not in the combinational `noc_rx_ready` path** (§10). |
| Tile resume | Containment applies to **one packet**. After the terminator, the NI is back in IDLE with counter 0. The next packet is offered to the tile normally. There is no quarantine: that would also drop legitimate traffic (e.g. matched memory responses). Blocking a tile is N-10 policy, driven by the persistent report. Cost: a tile that stalls every packet costs W extra cycles per packet. That is bounded, reported and counted. |
| Per packet vs per stall episode | Per packet (above). |

**W is derived, not picked.**
- **Production:** W_prod = S_tile + 1, where S_tile is the maximum legitimate tile-induced stall per packet allowed by the tile contract. S_tile is **OPEN-T1**, owned by the tile/SoC integration step (N-14). It cannot be derived yet.
- **RTL default:** `WD_LIMIT = 16`, marked in the RTL as a *test default*, not a production value.
- **Test points:** W ∈ {16, 64}. These are not tuned values. The two claims under test are:
  1. the trip occurs at exactly stall W and not at W−1;
  2. the extra delay grows with slope 1 in W.
- **Why 48 cycles apart:** to tell slope 1 from slope 0 given the arbitration uncertainty δ(0) = 12 (§9.5), the two W values must differ by more than 2δ(0) = 24. 64 − 16 = 48 > 24. The slope check runs with MAC off only.
- **Unit tests** also use W = 1, the degenerate edge.

## 6. DISCARD state (Q5)

```
             deliverable HEAD accepted              terminator accepted
   ┌──────► RX_IDLE ───────────────────► RX_PAYLOAD ──► (RX_MAC) ────────────┐
   │           │  ▲                           │            │                  │
   │  rejected │  │ rejected HEAD_TAIL,       │ expire_t,  │ F2/F5/F7         │
   │  HEAD, or │  │ orphan: stay IDLE         │ F2/F5/F7   │ (mid-packet)     │
   │  expire_t │  │                           ▼            ▼                  │
   │  in IDLE  └──┼────────────────────► RX_DISCARD ◄──────┘                  │
   │              │                    noc_rx_ready = 1 every cycle           │
   │              │                    consume every flit; tile sees nothing  │
   │              └──── accepted flit with terminator(k,type) ────────────────┘
   └──────────────────────────────── (back to RX_IDLE) ─────────────────────
```

**In RX_DISCARD:**
- `noc_rx_ready = 1` unconditionally. There are no `rx_*_valid` strobes to the tile.
- k keeps counting.
- The **only** exit is `accept_t && terminator(k, type)`.
- A HEAD or HEAD_TAIL seen at k ≥ 1 is counted as extra framing (F7) and **does not exit**, mirroring the allocator.
- `noc_rx_valid = 0` means wait. That is not a stall and not an error.

**Entry from RX_IDLE via `expire_t` (the HEAD was never accepted):**
- The HEAD is still on the wire.
- DISCARD starts at k = 0, so a HEAD_TAIL there is consumed as the terminator and the NI returns to IDLE the next cycle.
- A 2-bit encoding covers all four states (IDLE, PAYLOAD, MAC, DISCARD), so the RX state register does not widen.

**Entry actions** (the edge on which `rx_state_d = RX_DISCARD` and the cause is `expire_t`):
1. Set `ni_contain_sticky`. Increment `ni_contain_cnt`, saturating at 255.
2. If the sticky was clear, capture `ni_contain_info = {src_x, src_y, msg_type}`. Take it from `rx_*_q` if the HEAD was already accepted, otherwise from the presented head.
3. Pulse `rx_abort` for one cycle.
4. Reset the watchdog counter.
5. If the packet is a **matched memory response**, remember `{free_on_term, tag}` (Gap D).

**Transaction slot (Gap D).** A matched response frees its slot exactly once, at the accepted terminator of that packet. This applies whether the packet was delivered, aborted (F1/F2/F5/F7) or discarded by containment. A HEAD_TAIL MEM_WR_RESP frees at the HEAD_TAIL, as today. Freeing must not depend on the tile completing delivery, or N_OUTSTANDING=2 leaks and this NI's TX blocks permanently.

## 7. Persistent report, rule 4 (and MAC interaction)

New NI output ports go to the status/RoT side. They are **not** part of NI↔router, so M-F1 §8 is untouched.

| Port | Width | Semantics |
|---|---|---|
| `ni_contain_sticky` | 1 | Set on containment (`expire_t`). Cleared only by `rst` or `ni_status_clr`. **This is the acceptance criterion.** |
| `ni_contain_cnt` | 8 | Monotonic, saturating at 255. Cleared by `rst` or `ni_status_clr`. |
| `ni_contain_info` | 3+3+4 | src_x, src_y, msg_type of the first containment since the last clear |
| `ni_framing_sticky`, `ni_framing_cnt` | 1, 8 | Same rules, for F1–F10 |
| `rx_abort` | 1 (pulse) | To the tile: the packet in progress will not complete, so drop the partial data |
| `ni_status_clr` | 1 (in) | One-cycle clear. **Integration rule (N-14): it must be driven by the trusted RoT/status register, never by the local tile.** A tile that could clear its own sticky would erase the evidence. |

**Invariant I-N81-RPT.**
- `ni_contain_cnt` = min(255, number of `expire_t` events since the last `rst` or `ni_status_clr`).
- `ni_contain_sticky` = (that number ≥ 1).
- The same two rules hold for the framing pair.

If `ni_status_clr` and an event occur in the same cycle, **the event wins**: after that edge, sticky = 1 and cnt = 1. Otherwise a clear racing an attack could hide the attack.

**MAC interaction:**
- The terminator rule is identical in both modes (§3).
- MAC flits are never tile stalls, because the NI consumes them.
- A discarded packet's MAC is **not** checked and `rx_mac_valid` is never raised for it.
- A packet whose payload was delivered but which fails in its MAC region (F1/F2/F5/F7) raises `rx_abort`. The tile must therefore treat payload as provisional until `rx_mac_valid`. This is recorded for S8-5.

## 8. TX side — supply withholding (Gap B) and the store-and-forward decision

**Failure mode:**
- `TX_PAYLOAD: noc_tx_valid = tx_payload_valid`, so the NI injects the HEAD and then streams payload **from the tile**.
- If the tile stops supplying, the partial packet sits in the source router's LOCAL-in VC. Every output on its path stays locked, with no TAIL ever coming.
- Concrete case: SPOOF (2,1) sends an ATTEST_RESPONSE to RoT (1,1) and stops after the HEAD. That locks R5.W and **R4.L, the RoT's eject port**. After that, no tile can deliver anything to the RoT.
- The RX watchdog cannot help, because the RoT's NI sees `noc_rx_valid = 0`. That is not a tile stall at the RoT, and it is correctly not counted.

M-F1 rule 5 says "solely by withholding tile-side *consumption*", so it does not cover this case. See AM-2.

| Option | How | Verdict |
|---|---|---|
| **S1 store-and-forward** | New `TX_FILL` state. It collects all payload_n flits (≤16 × 32 b) from the tile, and only then enters TX_HEAD. From TX_HEAD to the terminator, `noc_tx_valid = 1` always; only the router's ready can pause it. | **Chosen.** The tile can stall only while nothing is in the network. |
| S2 TX watchdog + pad | On a supply stall, pad with BODY flits and a TAIL | Rejected. With MAC off there is no poison encoding, so the receiver would accept a padded packet as valid data. |
| S3 cut-through + credit reserve | Inject only when the whole packet fits downstream | Needs knowledge of downstream router state. Not possible without a router change. |

**TX packet object (rev 1).** It is fully specified, and nothing on the tile interface is invented.

Everything except the payload buffer **already exists** in today's RTL and is captured at request accept (`TX_IDLE && tx_valid && tx_ready && tx_dest_ok`, L490–515):

| Field | Storage | Captured | Source in RTL today |
|---|---|---|---|
| destination | `tx_dest_q` | request accept | L495 (existing) |
| msg_type | `tx_msg_q` | request accept | L496 (existing) |
| control, incl. the NI-allocated txn tag in `control[0]` for memory requests | `tx_control_q` | request accept (tag inserted by the NI) | L498, L515 (existing) |
| payload count n | `tx_payload_n_q` = `message_payload_flits(msg)` | request accept | L500 (existing) |
| MAC tag, 128 b | `tx_mac_tag_q` | **request accept, from the `tx_mac_tag` port. Unchanged.** | L506 (existing) |
| VC | not stored: `tx_vc = message_to_vc(tx_msg_q)` | combinational | L252 (existing) |
| length | not stored: `message_length(tx_msg_q)` | combinational | existing |
| **payload[0 … n−1]** | **new `tx_buf[16][32]`** | **TX_FILL, one per `tx_payload_valid && tx_payload_ready`** | **new** |
| fill index | new `tx_fill_cnt_q` (5 b) | TX_FILL | new |

**Consequences of that table:**
- **Where the MAC comes from is not decided here.** N-8.1 keeps exactly today's semantics: the 128-bit `tx_mac_tag` input is sampled when the request is accepted, and it is sent only when `MAC_ENABLE = 1`. Whether the MAC is later produced inside the NI or by crypto (so the port disappears, or changes timing) is **S8-2 / N-9**. Store-and-forward does not depend on that answer, because the MAC flits are sent from a register, never from the tile's live signals.
- `tx_mac_tag` has no valid/ready of its own, so a tile cannot use it to stall. At worst it can supply a wrong value, which is an S-8 integrity question, not a containment question.
- **Tile interface:** unchanged. It is the same `tx_valid/tx_ready` and `tx_payload_valid/tx_payload_ready` handshake; only the cycle on which `tx_payload_ready` is asserted changes (TX_FILL instead of TX_PAYLOAD).
- **Transaction-slot side effect:** the slot is still allocated at request accept (today's behaviour). A tile that stalls forever in TX_FILL holds **its own** slot, so only its own NI stops issuing. No network resource is held. This is intended.
- **Buffer:** 16 × 32 b per NI. The target is distributed RAM (LUTRAM). The area comes from the NI out-of-context (OOC) synthesis in step 10f; no number is claimed now.

**Latency cost (rev 1 formula).** T_fill is the number of cycles from request accept to the last payload handshake. Relative to today's streaming TX:
- The HEAD leaves **T_fill** cycles later.
- If the network does not backpressure, the TAIL leaves about **n + 1** cycles later when the tile supplies 1 flit/cycle (T_fill = n). This is because injection no longer overlaps supply.
- The general expression is ΔL_TX = T_fill + (network-side terms unchanged).
- No constant (such as "+16") is architectural. The real figures are N-8 measurements.
- Double-buffering is the known remedy if the cost matters.

**New TX SVA:**
- `a_tx_no_bubble`: `tx_state_q inside {TX_HEAD, TX_PAYLOAD, TX_MAC} |-> noc_tx_valid`.
- `a_tx_vc_legal` (§4).
- `tx_error` now also covers a reserved msg_type (8–15), and such a request is not sent (Gap C, AM-5).
- The TX state register grows from 2 to 3 bits (5 states).

## 9. SPOOF containment experiment (Q7) — finite and deterministic

### 9.1 Topology (XY routing; y+ = SOUTH, `NOC_XY_ROUTING.sv` L154)

The router index is i = y·3 + x.

```
 R0 CPU0(0,0) ──E──► R1 CPU1(1,0) ──E──► R2 MEMORY(2,0)
                                           │S
 R3 CRYPTO(0,1) ─E─► R4 RoT(1,1)          R5 SPOOF(2,1)
```

| Packet | Source → destination | msg_type (VC) | Flits (MAC off / on) | Count | Path (outputs taken) |
|---|---|---|---|---|---|
| **P_A** (victim wormhole) | CPU0 → SPOOF | ATTEST_RESPONSE (VC2) | 17 / 21 | 1 | R0.E → R1.E → R2.S → R5.L |
| **C1** a,b | CPU0 → CPU1 | MEM_WR_REQ (VC0) | 3 / 7 | 2 | R0.E (**contested**) → R1.L |
| **C2** a,b | CPU1 → MEMORY | MEM_WR_REQ (VC0) | 3 / 7 | 2 | R1.E (**contested**) → R2.L |
| **C3** a,b | CRYPTO → RoT | MEM_RD_REQ (VC0) | 2 / 6 | 2 | R3.E → R4.L (**disjoint control**) |

**Notes:**
- The TB tiles do not respond. N_OUTSTANDING = 2 therefore allows exactly the 2 requests per source.
- msg_type is chosen for length and VC only. M-F1 §10 imposes no initiator/message authorisation at transport level.
- **Shared physical inputs:** C1 and P_A share R1.W (VC0 vs VC2). C2 and P_A share R2.W. C3 shares nothing.

### 9.2 Storage when SPOOF stalls at the HEAD (variant A-S0, MAC off)

The 12-entry eject FIFO depth is **irrelevant**. What limits the eject path is the VC2 LOCAL credit (4). Everything beyond that backs up hop by hop, which is normal wormhole behaviour, not overflow. A flit in a link register or in the eject stage already holds its downstream credit, taken at grant.

| Location | VC2 flits of P_A | Which flits |
|---|---|---|
| R5 eject stage + eject FIFO (LOCAL credit 4) | 4 | 0 (HEAD) – 3 |
| R5 N-in VC2 (credit 4) | 4 | 4 – 7 |
| R2 W-in VC2 | 4 | 8 – 11 |
| R1 W-in VC2 | 4 | 12 – 15 |
| R0 L-in VC2 | 1 | 16 (TAIL) |
| **Total** | **17** | Locks held: **R0.E, R1.E, R2.S, R5.L** |

**Other variants:**
- **MAC on (21 flits):** R0 L-in holds 4 and 1 flit stays in the CPU0 NI TX (`noc_tx_valid = 1`, ready 0). C1 is then blocked at CPU0's NI instead of at R0.E. Same locks.
- **A-S1** (tile accepts HEAD + 3 BODY, then stalls; MAC off): 13 flits remain. Eject 4, R5.N 4, R2.W 4, R1.W 1 (TAIL). **R0.E is already released**, so only C2 is blocked. The TB expectation table encodes this per variant.

### 9.3 Injection schedule (identical prefix in every run)

1. At reset + 20 cycles, the CPU0 tile issues P_A, then C1a, then C1b (the NI TX serialises them).
2. **T_trig** is the cycle R1's `output_locked[E]` rises, i.e. P_A's HEAD is granted at R1.E. It is read by a hierarchical probe. At T_trig the CPU1 tile issues C2a and C2b, and the CRYPTO tile issues C3a and C3b.
3. Everything before SPOOF's first response to P_A is identical across B0, A and N0. So t0 (P_A's HEAD presented at the SPOOF NI) and T_trig are the same cycle in every run.

### 9.4 Runs

- **B0 (reference):** SPOOF tile `rx_ready = 1` always; watchdog enabled. It must end with `ni_contain_sticky = 0` everywhere.
- **A (attack):**
  - A-S0: `rx_ready = 0` from reset.
  - A-S1: accept HEAD + 3 BODY, then 0.
  - A-S2 (slow drip): `rx_ready = 1` for one cycle in every 4. Cumulative stall reaches W mid-packet. A per-episode watchdog (3 < W) would never trip; the TB's own model computes the exact expiry cycle.
- **N0:** A-S0 with `WD_ENABLE = 0` (§9.8).

**Per competing packet c, the TB records:**
- T(c) = cycle the destination NI accepts c's terminator;
- lock-release cycles for R0.E, R1.E, R2.S and R5.L;
- the expiry cycle.

### 9.5 Test acceptance bound derived from the frozen arbitration model

**Status of this bound.**
- It is derived from the RTL's arbitration model.
- It is **not** a formal proof.
- A measured value above it is a finding to root-cause. It is never a reason to raise the bound.

**Arbitration facts it rests on** (read from the RTL for rev 1):

| # | Fact | Source |
|---|---|---|
| AF1 | Stage 1 is a round-robin arbiter per physical input over its 3 VCs. `rr_ptr` advances to winner+1 **whenever `grant_valid`**, whether or not the flit actually moves. | `NOC_arbiter.sv` L134–143; `allocator.sv` `u_in_arbiter` |
| AF2 | Stage-1 requests come from `request_matrix`, which is **not credit-qualified**. It encodes only route + lock ownership (a locked output can be requested only by its owner). The credit check happens later (`transfer_valid`, M9). So a credit-starved owner VC still wins stage 1 in its turn and wastes that input cycle. | `allocator.sv` L176–222, L425–440 |
| AF3 | A locked output accepts only its owner. The lock is released only by the owner's TAIL. | `allocator.sv` L196–200, L470–476 |

**Consequence of AF1 and AF2.**
- At a physical input with exactly **two** active VCs, the arbiter strictly alternates. Each flit of one VC therefore waits at most **1** cycle because of the other, whether or not the other can move.
- With a active VCs the bound is (a − 1) cycles per flit. This experiment keeps a = 2 by construction.

**Model assumptions.** The TB checks A1–A5 and fails the run if any is violated.

| # | Assumption | TB check |
|---|---|---|
| A1 | The only injected packets are those in §9.1, on the schedule in §9.3. Nothing else is injected. | injection monitor = packet list |
| A2 | Every shared physical input (R1.W, R2.W) has at most 2 active VCs: P_A's VC2 and one competitor's VC0. | per-cycle count of non-empty VC FIFOs at R1.W, R2.W ≤ 2 |
| A3 | The contested outputs R0.E and R1.E serve P_A before any competitor. | lock owner = P_A's input VC at the first competitor request (vacuity check below) |
| A4 | B0, A and N0 share an identical prefix up to t0 (same reset, same schedule, same RTL build, same W, same MAC mode). | t0 and T_trig identical across runs |
| A5 | No reset during measurement; the pipe configuration is LINK_PIPE = 1, EJECT_PIPE = 1. | CONFIG banner |

**Claim 1 (exact).** In A-S0, `expire_t` fires at t0 + W − 1 and the first forced accept happens at t0 + W. This follows from the contiguous stall and §5.

**Claim 2 (shift).**
- By I-N81-WD, the SPOOF tile adds at most W stall cycles to P_A in every A variant.
- After that, the NI accepts one flit every cycle in which one is valid. That is the same service as B0's `rx_ready = 1` tile.
- Everything that depends on P_A therefore moves by at most W, apart from differences in arbitration interleaving.

**Arbitration term δ(M).**
- Under AF1, AF2 and A2, compare interleaving in A against B0:
  - each competitor flit can lose at most 1 cycle to P_A at its shared input;
  - each competitor flit can take at most 1 cycle from P_A, which delays a lock release and so every competitor behind that lock.
- Counting both effects in the worst case, the extra delay any single competitor sees is bounded by the total number of competitor flits that cross an input shared with P_A.
- Gaps (empty FIFOs) only remove contention, so they cannot increase this.

```
δ(M) = Σ over c' in {C1a, C1b, C2a, C2b} of L(c', M)      // each crosses exactly one shared input
δ(0) = 4 × 3 = 12          (MAC off, MEM_WR_REQ = 3 flits)
δ(1) = 4 × 7 = 28          (MAC on,  MEM_WR_REQ = 3 + 4 MAC flits)
```

**The TB computes δ(M) from its own packet list and `message_length()`.** It is never hard-coded. If the packet list changes, the bound changes with it.

```
Acceptance (c in {C1a,C1b,C2a,C2b}):  T_A(c,M,W) − T_B0(c,M)  ≤  W + δ(M)
Control    (c in {C3a,C3b}):          T_A(c,M,W) == T_B0(c,M)      (valid only with the §9.7 disjointness assertion)
Release order (A-S0):                 t_rel(R0.E) < t_rel(R1.E) < t_rel(R2.S) < t_rel(R5.L)
Slope (MAC off, A-S0):                |(Δ(c,W=64) − Δ(c,W=16)) − 48| ≤ δ(0)
T_bound(M,W) = max over c of ( T_B0(c,M) + W + δ(M) )    — used identically by A and N0 with the same (M, W)
```

**Where the "W + path + packet length" terms of M-F1 §10 sit.**
- T_B0(c) is a deterministic measured reference. It already contains c's path latency, its packet length and P_A's length, because in B0 P_A still passes through the contested ports.
- An absolute analytic path term would need the per-hop latency in cycles. That has **not been measured** (M-F1 §12 makes it an N-8 deliverable), and writing one down now would be a guess.
- δ, W and the shift argument are derived. T_B0 is measured, not assumed.

**Confidence.**
- The shift-plus-δ argument is an engineering derivation, not a formal proof.
- If a measurement exceeds the bound, that is a **finding to root-cause**. The bound must not be widened to make the test pass.

**Vacuity checks** (the test fails if contention never happened):
- In every A run, when C1a's HEAD first requests R0.E, the TB asserts R0.E is locked by P_A's input VC. Likewise for C2a at R1.E.
- These apply only to the variant that blocks that port.
- They are ignored in B0, where a port may already be free.

### 9.6 Drain criterion (after the last expected terminator, +32 cycles settle)

The network has drained when all of the following hold:
- All router input FIFOs and eject FIFOs are empty.
- All `qv_*` link valids and `eject_wr_q` are 0.
- All `in_v_*` are 0. This reuses the N-7 drain detector.
- Every credit counter is back at its reset value of 4.
- Every `output_locked` is 0.
- Every NI is in RX_IDLE and TX_IDLE.

### 9.7 Pass criteria for A

1. Every competing packet has completed within its bound, and its scoreboard payload matches (independent reference: the TB's own packet list).
2. C3 is cycle-exact against B0, **and** the resource-disjointness assertion held for the whole run.
   - Per-router flit monitors check that no C3 flit ever appears in R0, R1, R2 or R5.
   - They check that no P_A, C1 or C2 flit ever appears in R3 or R4.
   - They check that the R3 and R4 credit counters for every output *not* on C3's path stay at their reset value.
   - If the assertion fails, the equality check is void and the run FAILs. There is no fallback to a weaker equality.
3. The drain criterion holds.
4. P_A was **not** delivered complete to the SPOOF tile. In A-S1 and A-S2, `rx_abort` was seen.
5. At the SPOOF NI: `ni_contain_sticky = 1`, `ni_contain_cnt = 1`, and `ni_contain_info` = {0, 0, ATTEST_RESPONSE}. All other NIs show sticky 0.
6. **Persistence:** the sticky is still 1 at drain + 1000 cycles.
7. **Resume:** RoT then sends an ATTEST_REVOKE (HEAD_TAIL) to SPOOF with `rx_ready = 1`. It is delivered. The sticky is **still 1**, because good traffic does not clear it.
8. **Clear:** a 1-cycle pulse on `ni_status_clr` sets the sticky and counter to 0.

**Run matrix:**

| MAC | W | Runs |
|---|---|---|
| off | 16 | B0, A-S0, A-S1, A-S2, N0 |
| off | 64 | B0, A-S0 |
| on | 16 | B0, A-S0, N0 |

That is 10 runs.

### 9.8 Negative control N0 (Q8)

**Setup:** the same topology, packets and schedule, and the same T_bound(M, 16) from the B0 run in the same MAC mode M, with `WD_ENABLE = 0` and SPOOF `rx_ready = 0`.

**At T_bound, N0 must show all of the following:**
- C1a/b and C2a/b are **not** complete;
- C3a/b **are** complete, the same as B0;
- R0.E, R1.E, R2.S and R5.L are still locked;
- `ni_contain_sticky = 0`;
- no P_A flit moved in the last 256 cycles.

**Verdict:** the TB prints `N0 EXPECTED-FAIL CONFIRMED`. This counts as a PASS of the control. Any completion of C1 or C2 is an error.

**Why it is deterministic:** with the watchdog off, nothing in the design can release those locks, so the hang is permanent, not a race. The fixed T_bound turns that hang into a verdict. The same number that A must meet is the number N0 must miss, so the pair shows the watchdog is what makes the difference.

## 10. Timing, synthesis, FPGA vs ASIC

**Critical-path relevance.**
- `noc_rx_ready` feeds the router's `eject_rd = out_valid_local & out_ready_local`. That drives the eject FIFO read pointer and the LOCAL credit return.
- Today the path runs `noc_rx_flit` → head decode (dest, shape) → `noc_rx_ready`.
- N-8.1 adds the VC-match, length and msg_type ≤ 7 checks to that decode, estimated at about +1–2 LUT levels. The watchdog counter and the report registers are **off** this path.
- This path crosses the NI/router boundary, so it exists only in the integrated SoC top. The N-2.5 mesh gate never sees it.
- Step 10f: NI OOC synthesis with I/O delays budgeted against the router side. If that is tight, the fallback is to register the accept/reject decision. That costs one extra cycle per LOCAL delivery and needs no router change.
- **OOC results are not integrated timing.**
  - OOC synthesizes and times the NI alone, using assumed I/O delays. Its WNS is only as good as those assumed budgets.
  - The report for 10f will be: LUT / FF / LUTRAM / BRAM / DSP, internal WNS/TNS/WHS/THS, the internal critical path, and the I/O budget used, each labelled "OOC".
  - The NI↔router boundary path is closed only in the integrated top (N-14), and only then is it called "timing met".

**Synthesis.** Expected resources:
- RX: a 2-bit state, 3 counters (5, 5 and `WD_W` bits), 2 × 8-bit report counters, report registers.
- TX: a 16 × 32 LUTRAM, 3-bit state.

No latches: all FSM next-state logic is `always_comb` with defaults. Real numbers only after 10f.

**FPGA vs ASIC:**
- On FPGA the TX buffer is LUTRAM, which is cheap.
- In an ASIC it would be a 512-bit flop array or a small register file per NI: about 3 K flops across 6 NIs. An ASIC design would weigh that against a credit-reserve scheme (S3), which needs router changes.
- The watchdog design is the same on both.
